# WS2812 integration

The eight GRB WS2812 on GPIO27 use the unmodified official
[espressif/led_strip 3.1.1](https://components.espressif.com/components/espressif/led_strip/versions/3.1.1/readme),
Apache-2.0, pinned in `src/idf_component.yml`. Component Manager owns the
downloaded source and lockfile. This version supports ESP-IDF >=5.2, fixes
IDF 6.1 build compatibility and exposes custom RMT timing. No Arduino driver,
bit-banging, custom RMT encoder or PCM visualization is added.

## Signal and animation compatibility

The component's `LED_MODEL_CUSTOM` configuration supplies the working
Adafruit NeoPixel ESP32 timings: T0H/T0L = 400/850 ns, T1H/T1L = 800/450 ns.
At 20 MHz RMT resolution each bit is exactly 1.25 us (800 kHz). A 300 us LOW
reset follows every frame. The driver's GRB setting handles byte ordering.
GPIO27 is set LOW before startup logging; the worker sends a black frame
before its first animation. An unpowered strip cannot acknowledge data, so
physical strip presence is not detectable through this one-wire interface.

Before starting the RMT worker, `app_main` releases its own temporary GPIO27
reservation with ESP-IDF 6.1's `esp_gpio_revoke()`. This changes the SDK's
reservation mask, leaving the GPIO output actively LOW until RMT takes over.
Only GPIO27 is released, after its startup configuration and before any other
owner starts. `gpio_reset_pin()` would disable the output and enable pull-up,
so it is unsuitable for this handoff. The SDK is pinned; this private helper
must be rechecked when upgrading ESP-IDF. RMT warnings remain enabled.

Application code only selects colors and timing from the Arduino reference:

| State | RGB before global brightness | Timing |
| --- | --- | --- |
| Initializing | Point (255,80,0) | 100 ms per LED |
| Waiting | Head (0,48,255), previous LED (0,12,64) | 150 ms per step |
| Connected idle | All (0,96,112), scale 12..255 | 600 ms fade; 40 ms update |
| Playing | All (0,220,160), triangular scale 12..255 | 2400 ms cycle; 40 ms update |

`strip_animation.h` preserves both integer truncations: first `channel *
scale / 255`, then NeoPixel's `(channel * (brightness + 1)) >> 8`. With
brightness 48 the maximum byte is 48. No gamma correction is added.
Only state changes reset animation phase; identical frames are not sent.
Absolute monotonic time skips missed frames without queuing stale animation.

Ready/disconnected, connecting, reconnecting and pairing map to waiting.
Connected playback uses confirmed AVRCP status, with A2DP as fallback, just
like the existing Play/Pause control. This deliberately handles iPhone pause
while the A2DP stream remains open. Commands do not predict playback state.

## Ownership and audio isolation

`status_strip` is a priority-1 task, stack 3072 bytes, pinned to core 1. It
creates and exclusively owns the driver and pixel buffer; initialization on
that core also allocates the RMT interrupt there. It starts before Bluetooth
so the initialization animation can run during Bluetooth startup.

The application loop publishes only changed states through a one-slot queue
with `xQueueOverwrite`, without waiting. The worker checks the latest state
every 10 ms. No strip operation runs in a button callback or audio path.

RMT reserves 256 symbols (four 64-word hardware blocks). The complete frame
uses 192 data symbols, one reset symbol and one EOF. ESP-IDF 6.1's initial
encoding pass fills the whole allocation before transmission and disables
the threshold interrupt when encoding is complete. Thus these eight LEDs
do not need interrupt-driven mid-frame refill under Bluetooth load. A larger
strip would require revisiting this sizing; the relationship is asserted
at compile time.

The component's synchronous refresh waits for RMT completion inside this
worker; its API has no timeout parameter, including async completion.
That wait never holds a main-loop lock or blocks Bluetooth. If the driver
returns an error, the worker logs it once, disables further publication and
tries to delete its driver. The one-slot queue remains allocated so a racing
publisher cannot touch freed memory. Restart is required to retry. A stuck
driver wait would stop strip animation, while the independent main loop and
audio continue. GPIO2 remains a main-loop heartbeat, not an LED-task timer.

## Validation

Compile-time scenarios cover state precedence, head/tail wrap, exact RGB
bytes, fade endpoints, breathing symmetry and bounds, timing, immediate
transitions, repeated-state stability, unchanged-frame suppression and
delayed updates. The existing playback-policy tests cover AVRCP precedence
over A2DP. Signal integrity, actual colors and concurrent audio quality need
hardware testing; see [testing.md](testing.md).
